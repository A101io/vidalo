# BE-02 — Order confirmation mail from the payment webhook

*lane: backend (packages/core billing + reporter, apps/worker, apps/web checkout route) · estimate: 1 d · depends on: BE-01 (`mails.order`, `required` sentence) · complex: **yes** (webhook idempotency across paid/processing/async events, three plans, the mock path) · contract: `../02-architecture.md` §1, §4, §6, ADR-0008*

## Goal
Every buyer gets, within minutes of `checkout.session.completed`, one mail that confirms what
they ordered, what it cost, how it renews and ends, what happens next, which terms apply, and
who Vidalo is. Serves AC-14, AC-15; folds F-001, F-009, F-017, F-018, F-020.

## Acceptance criteria (from `01-brief.md`, AC-14 as amended by F-001)
- **AC-14** — Given a completed checkout, when the confirmation is built (`orderConfirmationEmail` for `setup`, `monitor` and `monitor_addon`, NL and EN; ADR-0008 moves it out of `welcomeEmail`), then the mail opens with an order block: product name, one-off amount and monthly amount excl. btw (btw shown separately), billing period, that Vidalo Monthly renews monthly and can be cancelled any month online with no notice period, a link to the terms and privacy statement, and the company line with btw number.
- **AC-15** — Given the mail test (`pnpm mail:lab`), when run, then the order block and the company line are asserted for both languages and both plans; control: removing the terms link turns it red.
- From R9 (F-001): the mail is queued from the webhook at `checkout.session.completed`, not from the set-up job, and also for `monitor_addon`.

## Contract
- `packages/core/src/billing/order-mail.ts` (new):
  - `export async function queueOrderConfirmation(business: BusinessRecord, session: Record<string, unknown>): Promise<"queued" | "duplicate" | "no_address">`
    reads `id`, `metadata.plan`, `payment_status`, `amount_subtotal`, `amount_total`, `total_details.amount_tax`, `currency`, `customer_details.email`, `locale`, `created`; refuses (`duplicate`) when an `order_confirmation.queued` event with this `sessionId` exists; validates the address with the address check the free check uses (`parseFreeCheckRequest`, `core/shared/free-check.ts:33`), else `no_address` + `log.warn("order_mail.no_address", { businessId, sessionId })`; enqueues `email` `{ template: "order_confirmation", … }` (§4) and logs `order_confirmation.queued { sessionId, plan, paid, jobId }`. No address in any log or event.
  - `export function mockCheckoutSession(plan, lang, email): Record<string, unknown>` — a session-shaped object from `PRICES` with 21% btw, `payment_status: "paid"`, `id: "mock_" + random`, for mock mode only.
- `billing/index.ts` `apply()` `case "checkout.session.completed"` (`:160-168`): call `queueOrderConfirmation(business, o)` first, for paid and processing alike, then the existing branches. `async_payment_succeeded` (`:170`) does not queue (the session id is the same, so it would be `duplicate` anyway; do not rely on that alone, do not call it).
- `reporter/templates.ts`: `export interface OrderData` and `export function orderConfirmationEmail(d: OrderData): Mail` (§6), blocks in this order: `p` intro → `cards` "Je bestelling" (ordered-on line, per-line amounts when `lines` is not null, subtotal, btw, paid/processing total; `processing` sentence when not paid) → `cards` "Looptijd en opzeggen" (`termsSetup` and/or `termsMonthly` by plan; `startNow` when `ownerVerified` or plan is `monitor_addon`, else `startAfterProof`) → `cards` "Wat er geldt" (terms link with `copy.legal.updated` — read, never edited — privacy link, `invoice`) → `note` `questions`. Links in the buyer's language (`/voorwaarden` → `/en/terms`). No `cta` button (nothing to do), so no primary-button question.
- `reporter/index.ts`: `deliverTo(...)` (private; recipient is `to`) and `export async function sendOrderConfirmation(job)`: refuses when `email.order_confirmation` with this `sessionId` exists; loads the business; builds `OrderData` (lines from `PRICES` only when they sum to `amounts.subtotal`, else `null` + event `order_mail.amount_mismatch`); sends with type `order_confirmation`, extra `{ sessionId }`.
- `shared/mail-prefs.ts:34`: add `"order_confirmation"` to `REQUIRED_MAIL_KINDS`.
- `apps/worker/src/jobs/types.ts:64`: the union member of §4; `jobs/misc.ts:86`: `case "order_confirmation": return { mode: (await sendOrderConfirmation(p))?.mode ?? null };`.
- `apps/web/app/api/checkout/route.ts:67-77` (F-009): when `getStripe()` is null and `!env.mock`, log `checkout.refused { reason: "no_stripe", plan }` and redirect `?betaling=fout`; only when `env.mock`, keep today's path and call `queueOrderConfirmation(business, mockCheckoutSession(plan, lang, business.ownerEmail ?? session email))` before the redirect.

- `scripts/mail-lab.mts:75-96`: `order_confirmation: { label: "Order confirmation after payment", to: "owner" }`; for that kind, problems when the text lacks `A101 B.V.`, `NL869514192B01`, a link to `/voorwaarden` or `/en/terms`, `btw`/`VAT`, or carries a `List-Unsubscribe` header; the paid journeys produce one per language (mock checkout path).
