Everything the other tickets compile against, working on MemDb with a deterministic mock seed, so

## Contract
From `02-architecture.md`, sections "Types", "Limits and access", "Parsing the owner's form", "Db",
`RunSummary.recommend`, "Mock seed". Exactly those names.

Files:
- `packages/core/src/types.ts`: `ProductLineStatus`, `ProductLineSpec`, `ProductLineCertificate`,
  `ProductLineOutlet`, `ProductLineData`, `ProductLineVersion`, `ProductLine`, `LineScope`,
  `LineFactsView`; `FactKey` + `FACT_KEYS` gain `spec`, `certificate`, `outlet`, `successor`;
  `CriteriumId` 1–16; optional line fields on `Facts`, `Prompt`, `Sample`, `ScanRun`, `Finding`,
  `ScanReport.productLine`.
- `packages/core/src/criteria.ts`: `LINE_CRITERIA` (13–16, ADR-0013 table), `criterium()` and
  `severityOf()` read `[...CRITERIA, ...LINE_CRITERIA]`, `FACT_KEY_CRITERIUM` gains the four keys.
  `CRITERIA` and `CRITERIUM_IDS` stay the twelve.
- `packages/core/src/shared/product-lines.ts` (new, exported from `shared/index.ts`):
  `PRODUCT_LINE_LIMITS`, `productLineAccess`, `lineScanRefusal`, `scannableLineMarkets`,
  `lineScopeOf`, `ProductLineFormInput`, `ProductLineField`, `ProductLineFieldError`,
  `parseProductLine`.
- `packages/core/src/prompts/slots.ts`: `SlotKind` gains `use` (60), `spec` (40), `certificate` (60);
  `SLOT_LIMIT` entries. Nothing else changes in the sanitiser.
- `packages/core/src/db/types.ts`: the new methods and the `line` scope parameters; `ScanRunCreate`,
  `FindingInput` gain the line fields; `SaveLineResult`.
- `packages/core/src/db/mem.ts`: all of it, including: business readers without `line` return only
  rows whose `productLineId` is null; `insertSamples` and `upsertFindings` set
  `productLineId`/`market` from the run and throw on a prompt of another scope or a move to
  another scope (mirror of `inherit_line_scope`); `upsertFindings` matches on line and market;
  `saveProductLine` / `setProductLineStatus` under `withLock`, version `max + 1`, versions never
  mutated (return copies).
- `packages/core/src/db/owner-area.ts`: `RunSummary.recommend?`; `summarizeRun` fills it from
  `report.recommendations` (sum of `named` and `answers`, top five `others` by answers);
  `runSummaries(db, businessId, limit, line?)`; `listReportArchive`, `dashboardRows` business-only
  (MemDb part here, SQL part in BE-02).
- `packages/core/src/copy/index.ts` + `en.ts`: `criteria[13..16]`, `factKey.{spec,certificate,outlet,successor}`
  (labels only; page copy is FE's), so typecheck stays green.
- `packages/core/src/shared/facts-nl.ts` + `facts-en.ts`: words for the four keys (how a wrong and a
  right value read: "800 g", "wel gecertificeerd" / "niet (meer) gecertificeerd", "niet in je lijst",
  "Tigris K5").
- `apps/web/lib/demo.ts`: `seedDemoLines(db, businessId)` per the seed table, called from
  `seedDemo` inside the MemDb branch after the business seed. Writes prompts (texts as BE-03's
  templates will produce them), three monthly runs per (line, market) with samples, claims, findings,
  fixes and saved summaries. Deterministic ids are not required; deterministic content is.
