# FE-02 — Add, edit and discontinue a line

*lane: frontend · estimate: 5 h · depends on: BE-01*

## Goal
A verified, paying owner adds a line, edits it (a new version) and marks it discontinued or active
again; anyone else cannot save and sees why. Serves AC1.

## Contract
Consumed (BE-01): `ProductLineFormInput`, `parseProductLine`, `ProductLineFieldError`,
`PRODUCT_LINE_LIMITS`, `productLineAccess`, `Db.saveProductLine`, `Db.setProductLineStatus`,
`countryOptions(lang)` (`core/shared/country.ts`).

Server actions in `apps/web/app/app/productlijnen/actions.ts` (new), exactly as the "Owner pages"
table in `02-architecture.md`:
- `saveProductLine(form)`: `requireOwnerOf(businessFromForm(form), next)` → `productLineAccess(business, session.userId)`
  (refused: event `product_line.refused {reason}`, redirect `fout=toegang:<reason>`) →
  `parseProductLine(formInput(form))` (first error → `fout=<field>[.<index>]:<reason>`) →
  `saveProductLine({ businessId, productLineId: line || null, data, maxActive: PRODUCT_LINE_LIMITS.lines })`
  (`limit` → event `product_line.refused {reason:"limit"}`, `fout=limiet`; `not_found` → redirect
  `/app/productlijnen`) → event `product_line.confirmed` → `revalidatePath` → redirect
  `/app/productlijnen/<id>?opgeslagen=1`.
- `setProductLineStatus(form)`: same gates; `status` must be `active` or `discontinued`.
- `formInput(form: FormData): ProductLineFormInput` in the same file: the field names from the
  contract; indexed groups read from 0 until the first index with no field present.

Form component `apps/web/app/app/productlijnen/LineForm.tsx` (client), rendered on
`/app/productlijnen?nieuw=1` and `/app/productlijnen/[id]?bewerken=1` (prefilled from `line.current`):
name, category (hint: "het woord waarmee klanten zoeken, bijvoorbeeld persfittingsysteem"), use
cases (textarea, one per line), markets (checkboxes from `countryOptions`, max
`marketsPerLine`), specifications (label + value rows, add/remove, max `specs`), certificates
(name, number, valid until as `type="date"`), where to buy (per chosen market: name + url rows),
replaces (textarea), replaced by. On submit it runs `parseProductLine` in the browser and shows
errors tied to their fields (`aria-describedby`, `aria-invalid`, focus to the first); the server
redirect `?fout=` shows the same message on render. Submit button "Bevestigen en opslaan" with the
sentence "Je bevestigt dat deze gegevens kloppen. We gebruiken ze vanaf de volgende maandelijkse
controle." Without access the form is not rendered; the banner (FE-01) shows instead. Works
without JavaScript (plain POST to the action; the server validates).
`?betwist=<findingId>` (from FE-04) shows one line above the form: "Je gaf aan dat AI hier gelijk
heeft. Pas de gegevens aan en bevestig."

Status button on the detail page (FE-03 places it): "Niet meer leverbaar" / "Weer actief" as a
small form posting to `setProductLineStatus`, with one sentence: discontinued lines are no longer
checked each month; open fixes finish.

Copy in `copy.productLines.form` and `copy.productLines.errors` (one sentence per
`ProductLineField` × reason that can occur), NL and EN. No price.
