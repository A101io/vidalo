# BE-02 — Migration 0020, PgDb, scoped readers, isolation test, RLS proof

*lane: backend · estimate: 5 h · depends on: BE-01*

## Goal
The data model in Postgres, with every invariant enforced there, PgDb matching MemDb, and the RLS
proof AC6 asks for. Serves AC6, AC7, and the data rules behind AC1–AC4.

## Contract
- `supabase/migrations/0020_product_lines.sql`: exactly the SQL in `02-architecture.md`, "Data
  model". **Do not apply it to the hosted project** (D4).
- `packages/core/src/db/pg.ts`: the BE-01 methods; `saveProductLine` / `setProductLineStatus` inside
  `withLock` (`pg_advisory_xact_lock`) in one transaction (count active, insert row + version, or
  insert version `max + 1`, update `updated_at`); `upsertFindings` key gains
  `product_line_id is not distinct from $ and market is not distinct from $`; every business reader
  without `line` adds `and product_line_id is null`: `listPrompts`, `listScanRuns`,
  `lastScanRunStartedAt`, `listFindings`, and the scan-run choice in `deleteScanRun`.
  Map the new columns in `mapPrompt`, `mapScanRun`, `mapSample`, `mapFinding`. `insertSamples` does
  not send `product_line_id`/`market` (the trigger sets them); `returning *` carries them back.
- `packages/core/src/db/owner-area.ts`: SQL halves of `listReportArchive`, `runSummaries` (with
  `line`), `dashboardRows`, `openFixesByFinding`: business-only unless a `line` is passed.
- Isolation test `packages/core/test/product-lines-isolation.test.ts` (runs on MemDb and, under
  `verify:pg`, PgDb): seed a business with a full business run and a line run with findings; assert
  `listPrompts`, `listScanRuns`, `listFindings`, `lastScanRunStartedAt`, `listReportArchive`,
  `runSummaries`, `dashboardRows`, `buildReport(businessRun)` return exactly what they return without
  the line. A comment in the file says: a new business reader is added here.
- `scripts/rls/product-lines.sql`, in the style of `scripts/rls/membership.sql` (one rolled-back
  block ending in `raise exception 'RLS-OK …'`, `-v broken=1` control recreates
  `member_product_line` as `using (true)` and must give `RLS-FAIL`): login 1 owns business A with two
  lines (the control that must see 2 lines, 2 versions), login 2 owns business B with one line;
  as `authenticated` with login 1's claims: 2 lines; with login 2's: 1; as `anon`: 0; insert,
  update and delete on both tables as `authenticated` are denied; an update of a
  `product_line_facts` row as the owner role raises (immutable trigger). Wire it into
  `scripts/verify-pg.sh` after `membership.sql`.
- Trigger tests on PgDb in the db test suite: a sample whose prompt is of another line raises; a
  finding update to another line's run raises; a business sample in a business run keeps nulls.
