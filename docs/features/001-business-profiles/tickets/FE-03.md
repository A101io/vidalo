# FE-03 — The owner corrects the profile on /app/gegevens

*lane: frontend · estimate: 3 h · depends on: BE-01 (types, `parseOwnerProfile`, `effectiveProfile`, MemDb `setOwnerProfile`)*

## Goal
A paying, verified owner sees what Vidalo checks their business as and can correct mode, offer,
audience and category; a correction is never overwritten by a later automatic one. Serves
Amendment A1 ("a paying owner can correct it on `/app/gegevens`"), AC-8 (the profile group).

## Contract
```ts
// @vidalo/core/scanner
effectiveProfile(b: Pick<BusinessRecord, "profileAuto" | "profileOwner">): BusinessProfile | null;
parseOwnerProfile(fields: { mode?: string; offer?: string; audience?: string; category?: string }, current: BusinessProfile | null):
  { ok: true; profile: BusinessProfile } | { ok: false; field: "mode" | "offer" | "audience" | "category"; reason: "required" | "refused" | "too_long" };
// Db
setOwnerProfile(businessId: string, profile: BusinessProfile): Promise<void>;   // writes profile_owner only
```
Server action `saveProfile(form: FormData)` in `apps/web/app/app/gegevens/actions.ts`:
1. `const { business } = await requireVerifiedOwner("/app/gegevens")` (the business comes from the
   session; never read a business id from the form).
2. `parseOwnerProfile({mode: form.profileMode, offer: form.profileOffer, audience: form.profileAudience, category: form.profileCategory}, effectiveProfile(business))`.
3. Error → `redirect(href("/app/gegevens?profielfout=<field>:<reason>#profiel"))`.
4. OK → `db.setOwnerProfile(business.id, profile)`; `db.logEvent(business.id, "profile.corrected", { from: previousMode, to: profile.mode })`;
   `revalidatePath("/app/gegevens")`; `redirect(href("/app/gegevens?profiel=1#profiel"))`.

UI, a group with `id="profiel"` on `/app/gegevens`, its own `<form>`:
- `<fieldset>` with `<legend>` "Zo controleren we je bedrijf" and three radios in customer words:
  "Klanten komen bij mij langs" (`door`), "Ik kom bij de klant" (`visit`), "Ik werk online of door
  heel Nederland" (`online`); under each one line of what it asks (e.g. online: "Vragen naar wat je
  doet, je website en wie AI noemt voor jouw soort aanbod; geen openingstijden of adres").
- Text inputs with labels: "Wat bied je aan" (`profileOffer`, maxLength 120), "Voor wie"
  (`profileAudience`, 80), "Hoe zoekt een klant naar jou" (`profileCategory`, 60, hint "een
  zelfstandig naamwoord, bijvoorbeeld ‘aanbieder van achtergrondmuziek’"). Prefilled from
  `effectiveProfile`; a line "Automatisch bepaald" or "Door jou aangepast" with the date (`decidedAt`).
- Errors: from `profielfout`, shown next to the field, input `aria-invalid="true"` and
  `aria-describedby` to the message; the message is also in an `aria-live="polite"` region at the
  group's top. Success: a short confirmation there.
- The submit is a secondary button ("Opslaan" style of a secondary action): the page keeps one
  primary button (the facts form's).
- Copy NL + EN under `copy.app.facts.profile` (or the file's existing section for this page).
