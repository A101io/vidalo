# BE-06 — Judging an online business: identity:kind, town-free naming, families and quotes

*lane: backend · estimate: 4 h · depends on: BE-01*

## Goal
Answers to an online business's questions are judged by the stipregel unchanged, with a
mis-described business caught on criterium 11, and the report carries what the competition block
needs. Serves AC-5 (data), AC-6, AC-A6.

## Contract
Read ADR-0005.
- `scanner/normalize.ts factValue(facts, "identity", "kind")` → `"same"` when `facts.profile?.grounded`
  and `facts.profile.offer`, else `null`. Other identity subjects unchanged.
- `scanner/extract.ts`:
  - rules extractor: probe `identity:kind` → `same` when the answer shares a content word (≥ 4
    letters, stop words out) with `profile.offer` or `profile.category`; `other` when it calls the
    business a kind from a short list that the offer does not contain (winkel, shop, webshop,
    restaurant, kapper, hoortoestel, audicien, makelaar, bakkerij, garage, store, hearing) ; not-found
    patterns as today.
  - LLM extractor: the user JSON gains `profiel: {aanbod, categorie}` when present; the schema
    description says identity with subject "kind": `same` (described as this kind of business) |
    `other` (described as a different kind); `postNormalise` passes `same`/`other`.
  - `mentionsBusiness(answer, facts)`: when `facts.profile?.mode === "online"` the place is not
    required for a one-word name.
  - `detectOtherEntity(answer, facts)`: when online, skip the "in <other city>" loop and the
    "dit gaat over … in" test; keep `namesOnlyAnotherBusiness`.
- `scanner/recommendations.ts summarizeRecommendations`: each summary gets `family`
  (`online.rec.*` → `rec_category`, `online.alt.*` → `alternative`, else `rec_town`) and `quotes`
  (≤ 3; for `rec_category`/`alternative` only: sentences of answers that `mentionsBusiness` and
  contain none of the summary's `others`; ≤ 240 chars at a word boundary; first per engine first,
  then by answer order; `{text, engine}`). Sort order keeps local rows as today.
- Copy needed by the report for the finding line (`"beschreven als een ander soort bedrijf"`) is FE-02's.

## Done when
- [ ] AC-6 orange fixture (through `runScan` with fixed engine clients, the same path a real report uses): ChatGPT answers "Wat doet Sonable?" with "Sonable is een winkel aan de Weena 705 in Rotterdam en is op zondag open." → an `identity`/`kind` finding, criterium 11, `stip` orange or worse
- [ ] AC-6 green fixture: every answer about Sonable right (existence, what = same, website), Sonable in 0 category answers → `stip` green; `recommendations` show `named: 0`
- [ ] An ungrounded profile: "wat doet X" answers are unchecked (`asked[].checked === false`), never correct
- [ ] An online one-word name ("Sonable") is `named` in a list answer without "Rotterdam"; "Sonable is gevestigd in Amsterdam" is not an other-entity answer for an online business, and still is for a door business
- [ ] Quotes never contain a name from `others`; at most 3; none on `rec_town`
- [ ] Unit test on the summary: `named + (answers without the business)` adds up to `answers` per question
- [ ] Tests written and shown to fail without the change
- [ ] No secret, no personal data in logs
