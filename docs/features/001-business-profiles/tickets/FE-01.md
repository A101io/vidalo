# FE-01 — The waiting page shows what Vidalo is doing

*lane: frontend · estimate: 5 h · depends on: BE-01 (types only)*

## Goal
`/scan/[token]` (NL and `/en/scan/[token]`) shows the scan's real steps as they happen, animated in
design G, accessible, and working without JavaScript. Serves AC-A9, AC-A10, AC-8 (waiting page).

## Contract
Consumed, not built here (BE-07 builds it; until it lands, use fixtures of this exact JSON):
```ts
// GET /api/scan/[token]/status  → 200, cache-control no-store
{
  status: "queued" | "running" | "done" | "failed";
  stage: "understand" | "choose" | "ask" | "compare" | "done";
  profile: { mode: "door" | "visit" | "online"; offer: string | null; audience: string | null; category: string | null; source: "auto" | "owner" | "fallback" } | null;
  questions: { id: string; text: string }[];            // asking order, scan language (Dutch for NL businesses)
  engines: { engine: Engine; received: number; expected: number }[]; // expected can grow during "ask"
  reportUrl: string | null;                             // "/r/<scanRunId>" when done
}
// 404 { status: "missing" }
```
The server component reads the same state with `getScanState(token)` (`ScanJobState` v2 from
`@vidalo/core/scanner`) and passes it as initial props.

What the page shows, in order (labels from copy by stage key, never from the state):
1. **Je bedrijf begrijpen** (`understand`): once `profile` is known, one sentence under it, e.g.
   "Sonable: achtergrondmuziek voor hotels en horeca, online en door heel Nederland." Built from
   `profile` by a copy function per mode; a `fallback` profile with null slots shows the mode words only.
2. **De juiste vragen kiezen** (`choose`): the questions, each entering when first rendered.
3. **Vragen aan ChatGPT en Google AI** (`ask`): one row per engine with `ENGINE_LABEL`, a dot, and
   "n antwoorden" (`received`); `expected` is not shown as "n van m" while it can still grow.
4. **Antwoorden lezen en vergelijken** (`compare`).
5. Report: the existing redirect when `status === "done"` (`router.replace`, and `redirect()` on
   the server render).
`failed`: the existing "De controle is niet gelukt" + "Opnieuw proberen".

Mechanism (ADR-0006):
- Poll every 2 s as today; stop on `done`/`failed`.
- Motion is CSS only, in a stylesheet for this page (e.g. `app/scan/[id]/waiting.css` imported by
  the component, or a block in `app/scenes.css`): a mount keyframe (fade + 8–14 px rise, 300–400 ms)
  on new step and question rows, `animation-delay` staggering the question list, a slow pulse on
  the active step's dot. `@media (prefers-reduced-motion: reduce) { animation: none }` for all of it.
  No `data-motion` attribute on this page; `public/motion.js` is not touched.
- Design G: white ground, one blue accent at most, status colours only in dots (done = green,
  active = amber "bezig", waiting = line grey), no emoji, no exclamation marks, no dark mode;
  phone width 390 px without horizontal scroll.
- No JavaScript: the server render shows the current state; add
  `<noscript><meta httpEquiv="refresh" content="5" /></noscript>` and, inside `<noscript>`, a text
  link "Vernieuwen" to the same URL.
- Accessibility: one visually hidden `<p aria-live="polite">` holding a single sentence for the
  current stage (plus the profile sentence when it appears); the counters are not live. The step
  list is an `<ol>`; the active step has `aria-current="step"`; dots are `aria-hidden`; every state
  is told in text, not only by colour.

Copy (NL in `packages/core/src/copy/index.ts`, EN in `en.ts`, under `copy.scan`): `stages.understand`,
`stages.choose`, `stages.ask(engines: string)`, `stages.compare`, `stages.done`,
`profileSentence(p: ProfileSummary, name: string)`, `answers(n: number)`, `refresh`. Remove
`scan.steps` once nothing reads it. No GEO, AEO, LLM, prompt, platform, zichtbaarheid, ranking.
