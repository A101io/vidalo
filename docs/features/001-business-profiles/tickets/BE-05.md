# BE-05 — Question library: usable rule, ledger writes, proven/retired picks, `pnpm library`

*lane: backend · estimate: 4 h · depends on: BE-01, BE-03 (`selectQuestions` calls `pickTemplates`)*

## Goal
Every scan records how often each question was asked and gave a usable answer; online checks
prefer templates proven for their category and never ask retired ones; Julian can read the list.
Serves AC-A7 and Amendment A3.

## Contract
Read ADR-0004; it is the rule.

`packages/core/src/prompts/library.ts`:
```ts
export const PROVEN_MIN_ASKED = 20, PROVEN_MIN_SHARE = 0.6, RETIRE_MIN_ASKED = 50, RETIRE_BELOW_SHARE = 0.3;
export type LibraryStatus = "proven" | "trial" | "retired";
export function libraryStatus(row: { asked: number; usable: number }): LibraryStatus;
export function isUsable(args: { prompt: PromptLike; verdict: SampleVerdict | undefined; answerText: string; claims: Claim[] }): boolean;
export function pickTemplates<T extends { key: string; family: QuestionFamily }>(family: QuestionFamily, n: number, builtIns: T[], rows: LibraryRow[]): T[];
export function templateKeyOf(prompt: Prompt, mode: ProfileMode): string;   // prompt.templateKey ?? `${mode}.${kind}.${category}${intent ? "." + intent : ""}`
export function templateTextOf(prompt: Prompt, facts: Pick<Facts, "name" | "place">): string; // name → {naam}, place → {plaats}
export function useRows(args: { scanRunId: string; profile: BusinessProfile; facts: Facts; prompts: Prompt[]; samples: Sample[]; claimsPerSample: Claim[][]; verdicts: Map<string, SampleVerdict> }): QuestionUseInput[];
```
- `isUsable`: recommendation → verdict `named` or `namedBusinesses(answerText).length > 0`; about →
  verdict in `correct | wrong | other_entity | not_found`, or a claim with a value for the prompt's
  probe (an unchecked value). Otherwise not usable.
- `useRows`: one row per template key per scan (sum over prompts sharing a key); category =
  `profile.category ?? "onbekend"` sanitised; family from `familyOf`.
- `pickTemplates` (ADR-0004 "Pick"): only for `rec_category` and `alternative` in online mode.
- `runScan`: after compare, `db.recordQuestionUse(useRows(...))` in a try/catch (failure → event
  `library.record_failed`, scan unaffected); for each online `rec_category`/`alternative` key whose
  status was not `retired` before and is after, `logEvent(null, "library.retired", {category, mode, templateKey})`.
- `loadPrompts` (online): reads `db.questionLibrary({category, mode:"online"})` (failure → built-in
  order) and passes rows to `selectQuestions` → `pickTemplates`.
- `pnpm library` (root script → `packages/core/src/cli/library.ts`): reads `questionLibrary()`,
  writes `out/library.md`: a "Gestopt" (retired) table first, then per category a table
  `vraag | modus | gevraagd | bruikbaar | status`, share as "n van m" plus status word, never a bare
  percentage (house rule); prints the path. Works on MemDb (mock) and PgDb (`DATABASE_URL`).
- `docs/RUNBOOK.md` gains how Julian reads it in production: the SQL editor link
  `https://supabase.com/dashboard/project/bbynmqvaxpjdnkaasutd/sql/new` and the query
  `select category, mode, template_nl, asked, usable, usable_share from question_library order by category, mode, asked desc;`

## Done when
- [ ] AC-A7 on MemDb and PgDb: three scripted full online scans in one category record their templates with counts; with the counts made so that `online.rec.trust` and `online.rec.price` are proven and `online.rec.audience` is not, a fourth business in that category gets, in its free check (two `rec_category` slots), the proven pair instead of the default `rec.audience`, `rec.quality` (a full check asks all four `rec_category` templates that are not retired, so the difference shows in the free check)
- [ ] A template at 50 asks and < 30 % usable is never asked again in that category, is listed first in `out/library.md`, and `library.retired` is logged once
- [ ] Door and visit scans record rows (key `door.about.hours` …) but their question sets are unchanged (BE-03 snapshot still green)
- [ ] A failing `recordQuestionUse` does not fail the scan
- [ ] Tests written and shown to fail without the change
- [ ] No secret, no personal data in logs; `out/library.md` contains no business names (templates carry `{naam}`)

## Not in this ticket
- Templates written or approved through a screen (A6); clustering similar categories.
