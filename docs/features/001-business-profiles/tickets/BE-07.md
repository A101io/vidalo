# BE-07 — Progress events, ScanJobState v2, status endpoint

*lane: backend · estimate: 2 h · depends on: BE-01*

## Goal
The waiting room's state reflects the scan's real steps (understand, choose, ask with per-engine
counts, compare, done), and `GET /api/scan/[token]/status` returns it in the contract's shape.
Serves AC-A9 (data side).

## Contract
Read ADR-0006. Shapes are in `02-architecture.md` "Waiting-room state and the status endpoint":
```ts
type ScanStage = "understand" | "choose" | "ask" | "compare" | "done";
interface ScanJobState { token; businessId; scanRunId; status; stage; profile: ProfileSummary | null; questions: { id: string; text: string }[]; engines: { engine: Engine; received: number; expected: number }[]; error?: string | null; }
// GET /api/scan/[token]/status → 200 { status, stage, profile, questions, engines, reportUrl } | 404 { status: "missing" }; cache-control: no-store; never `error`
```
- `runScan` emits: `profile` (after `ensureProfile`; until BE-04 lands, emit the door profile it
  uses), `questions` (after `loadPrompts`: `{id, text: textNl}` in asking order), `start` with
  `perEngine` (first-round samples per engine), `escalate` with the samples added per engine before
  round 2, `asked` and `phase` as today.
- `scanner/progress.ts runScanWithProgress` maps: start state `queued/understand`; `profile` →
  `stage:"choose"`, `profile` set; `questions` → `questions` set; `start` → `stage:"ask"`, `scanRunId`,
  `engines[].expected` from `perEngine`, `received: 0`; `asked` → `received++` for that engine;
  `escalate` → `expected += n`; `phase extract|compare` → `stage:"compare"`; done → `stage:"done"`,
  `status:"done"`. Writes stay coalesced through `flush()`. Mail and `REPORT_EMAIL_EVENT` behaviour unchanged.
- `apps/web/lib/core.ts`: `createScanState` builds the v2 initial state (no copy argument needed;
  keep the parameter only if callers need it); `progressTemplate` removed with its last caller;
  `GET /api/scan` (the info endpoint) returns stage keys instead of labels.
- `apps/web/app/api/scan/[id]/status/route.ts`: the v2 response; a stored state without `stage` →
  `stage:"ask"`, `questions: []`, `engines: []`, `profile: null`.
- `apps/worker/src/cloudflare.ts`: unchanged apart from types (it calls `runScanWithProgress`).
