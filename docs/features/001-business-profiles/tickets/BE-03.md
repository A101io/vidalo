# BE-03 — Questions by profile: families, online templates (NL/EN), loadPrompts

*lane: backend · estimate: 5 h · depends on: BE-01 (types, `sanitizeSlot`)*

## Goal
The question set follows the profile's mode by the A2 table; local businesses keep main's
questions text for text; online businesses get the town-free set; every slot value is cleaned or
refused. Serves AC-2, AC-3 (as amended), AC-A2, AC-A5, AC-A8, AC-7 (pack parity).

## Contract
Read ADR-0003 first; the family table there is the rule.

New files:
- `packages/core/src/prompts/slots.ts` (sanitiser from BE-01): add `fillTemplate(template, slots)`,
  which accepts only values that went through `sanitizeSlot` (a branded type `SlotValue`).
- `packages/core/src/prompts/profile.ts`: `familyOf(prompt)`, `applies(family, profile, facts)`,
  `selectQuestions(...)` (one exported entry point used by `loadPrompts`), `competitorsInUse(profile, previousSamples, facts)`.
- `packages/core/src/prompts/online.ts` and `online.en.ts`: `ONLINE_TEMPLATES` in this order, same keys in both files:

  | key | family | intent | NL | EN |
  |---|---|---|---|---|
  | `online.existence.exists` | existence | — | Bestaat {naam} nog? | Does {name} still exist? |
  | `online.existence.active` | existence | — | Is {naam} nog actief? | Is {name} still in business? |
  | `online.what` | what | — | Wat doet {naam}? | What does {name} do? |
  | `online.website` | website | — | Wat is de website van {naam}? | What is the website of {name}? |
  | `online.phone` | phone | — | Wat is het telefoonnummer van {naam}? | What is the phone number of {name}? |
  | `online.rec.audience` | rec_category | specialty | {Welke} {categorie} is goed voor {doelgroep}? | Which {category} is good for {audience}? |
  | `online.rec.quality` | rec_category | quality | Wat is {de beste} {categorie}? | What is the best {category}? |
  | `online.rec.trust` | rec_category | trust | {Welke} {categorie} raad je aan? | Which {category} do you recommend? |
  | `online.rec.price` | rec_category | price | {Welke} {categorie} is betaalbaar? | Which {category} is affordable? |
  | `online.alt.self` | alternative | alternative | Wat is een goed alternatief voor {naam}? | What is a good alternative to {name}? |
  | `online.alt.competitor` | alternative | alternative | Wat is een goed alternatief voor {concurrent}? | What is a good alternative to {competitor}? |

  Probes: existence → `existence`; what → `identity:kind` (category `identity`, criterium 11, kind about);
  website → `website`; phone → `phone`; rec_category → `existence:<INTENT_SUBJECT[intent]>` (kind
  recommendation, criterium 6, 9 for price); alternative → `existence:alternatief`.
  `{Welke}`/`{de beste}` use `welkFor`/`deBesteFor` on the head noun (words before the first
  " van | voor | met | in | uit ").

Sets: online free = `existence.exists`, `what`, `website`, two `rec_category` (pick from BE-05's
`pickTemplates`; until BE-05, default order `rec.audience`, `rec.quality`; `rec.audience` needs an
audience, else the next), `alt.self`. Online full = both existence, what, website, phone when
`facts.phone`, four `rec_category`, `alt.self`, one `alt.competitor` per `competitorsInUse` (≤ 3;
profile competitors, else the three names most often in `others` of the previous online scan's
`rec_category`/`alternative` samples; every name through `sanitizeSlot(…, "competitor")`; the business
itself dropped by `mentionsBusiness`/`normalizeName`). Without a category the rec_category
templates are skipped (4 questions in a free check).

`scanner/index.ts loadPrompts(db, businessId, facts, kind, sector, promptIds, now, profile, library)`:
- `door`: today's body unchanged, plus drop stored prompts whose `templateKey` starts with `online.`.
- `visit`: today's body, then keep only prompts where `applies(familyOf(p), profile, facts)`.
- `online`: generate with `selectQuestions`, insert missing (with `templateKey`) by text, return the
  stored rows whose text matches, in template order.
`prepareBusiness` (`scanner/onboard.ts`) no longer inserts prompts; `Prepared.prompts` becomes the
stored list (may be empty); update the CLI line that prints the count.
