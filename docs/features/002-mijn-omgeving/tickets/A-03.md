# A-03 — Link limits, safe `next`, Origin check, fresh sign-in for the irreversible

*lane: A (Opus) · estimate: 6 h · depends on: C-00, A-02 (same lane)*

## Goal
Link requests are limited per address and IP and answer identically for every address; no
`next` value leaves the site; a cross-site POST to a route handler changes nothing; deleting
and changing the address need a sign-in from the last 15 minutes and return to the same step.
Serves AC-4 (a), (b), (c), (e); AC-5 (c) (address change; the delete step is A-05).

## Contract
From `02-architecture.md` "Sign-in link" and "Session" (fresh sign-in):
- `core/shared/safe-next.ts`: `export function safeNext(raw: string | null | undefined, fallback?: string): string;` (default `"/app"`).
  C-00 already ships the safe body (incl. the post-normalisation check, F-023); this ticket
  owns its test table and wires it into every caller.
- `core/shared/auth-throttle.ts`: `export const LINK_LIMITS = { perAddress: 5, perIp: 20, windowMs: 3_600_000 } as const;`

  `export function overLimit(counts: [number, number]): boolean;`
- Db: `throttleAuth`, `pruneAuthThrottle` (shared contract §2) in types/MemDb/PgDb.
- `core/shared/same-origin.ts`: `export function refuseCrossSite(req: Request, baseUrl: string): Response | null;`
- `apps/web/lib/env.ts`: `authSecret` (`VIDALO_AUTH_SECRET`; `"vidalo-local"` only without Supabase; throws at use when Supabase is configured and it is missing).
- `apps/web/lib/fresh-sign-in.ts`: `export async function requireFreshSignIn(next: string): Promise<Session>;`
  → `redirect(href("/inloggen?opnieuw=1&next=" + encodeURIComponent(next)))` when not fresh.
- `sendMagicLink`: format → Turnstile → throttle → Supabase; `safeNext` replaces both inline
  checks (`sendMagicLink`, `claimBusiness`); `confirmSignInAction` uses `safeNext`.
- `/inloggen?opnieuw=1`: one sentence why, the address pre-filled from the session.
- `POST /auth/uitloggen` and `POST /api/billing/portal`: `refuseCrossSite` first.
- `saveMailPrefs`: `requireOwnerOf(businessFromForm(form))` (F-020).
- `changeEmail`: `requireFreshSignIn("/app/account?stap=email#inlog")`; "bezet" when the new
  address owns a business not in `listMyBusinesses(session)`.

Consumes from lane B: `listMyBusinesses(session)` (`apps/web/lib/active-business.ts`; the C-00
stub is enough for every test here).

## Tests
- `safe-next.test.ts`: each of `//evil.example`, `/\evil.example`, `/%2F%2Fevil.example`,
  `/%5Cevil.example`, `https://evil.example`, `javascript:alert(1)`, `/%252F%252Fevil.example`,
  `/\t/evil.example`, `/.//evil.example`, `/app/..//evil.example`, `/%2e%2e//evil.example`,
  `/a/../%09/evil` (F-023), `""`, `null` → `"/app"`; `/app?x=1#y`, `/en/app/account` kept.
- A route-level table: for each bad `next` passed to `/inloggen` (form), `/auth/confirm` (POST),
  `/auth/callback` (GET) and the link-business button, every `Location` header is relative or
  on `PUBLIC_BASE_URL`'s host.
- `auth-throttle.test.ts` (MemDb and PgDb, fake clock): the 6th request for one address in an
  hour is over; 21st from one IP is over; after 61 min the address is under again; keys are
  64-hex and differ from the raw address; a different secret gives different keys.
- AC-4(a): the action's response and the rendered `/inloggen?sent=1` body are byte-identical
  for an address with a business, with only an account, and unknown (mock and with the fake
  GoTrue from A-01).
- `same-origin.test.ts`: `Origin: https://evil.example` → 403; own host → null; no Origin +
  `Sec-Fetch-Site: same-origin` → null; no Origin and no header → 403. Route tests: a foreign
  POST to `/auth/uitloggen` leaves the session usable; to `/api/billing/portal` creates no
  portal session.
- Fresh sign-in: `changeEmail` with `signedInAt` 16 min ago redirects to
  `/inloggen?opnieuw=1&next=…`; after a new sign-in the owner lands on the open address form.
