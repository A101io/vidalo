# A-01 — Session refresh in middleware, safe auth cookies (failing test first)

*lane: A (Opus) · estimate: 5 h · depends on: C-00*

## Goal
The owner stays signed in while using the site across access-token expiries, and every auth
cookie is HttpOnly, Secure on https and SameSite=Lax. Serves AC-3 (a), (b).

## Contract
Implements `02-architecture.md` "Session (lane A, ADR-0002)", first two paragraphs:
- `apps/web/lib/auth-cookies.ts` (edge-safe, no core import):
  `export const AUTH_COOKIE_MAX_AGE = 90 * 86400;`
  `export function authCookieOptions(baseUrl = process.env.PUBLIC_BASE_URL ?? ""): { httpOnly: true; secure: boolean; sameSite: "lax"; path: "/"; maxAge: number }`
  (`secure` = `baseUrl.startsWith("https:")`).
- `apps/web/middleware.ts`: refresh as specified (only when a `sb-` cookie is present and
  Supabase is configured; `getClaims()`; response built after the await; forwarded `cookie`
  header updated; pending cookies set with `authCookieOptions()` forced; the headers `setAll`
  receives as its second argument applied; `Cache-Control: private, no-store` on every
  response carrying an `sb-` `Set-Cookie`, F-018). The language and
  gate logic, the `keep` rule for OpenNext's second pass and the matcher stay as they are. No
  database, no `@vidalo/core/shared` import (only `shared/gate`).
- `apps/web/lib/supabase.ts`: `createServerClient(…, { cookieOptions: authCookieOptions(), cookies: … })`;
  `setAll` forces the same options and, where it can write (route handler, action), sets
  `Cache-Control: private, no-store`; the server-component catch stays.

Consumes from lane B: nothing.

## Tests
- `e2e/fixtures/fake-gotrue.ts`: HTTP server on `127.0.0.1:54399` (verify, refresh with
  rotation and reuse detection that revokes, user, logout, jwks), HS256, 5-second access
  tokens. `playwright.auth.config.ts`: `next dev --webpack --port 3102` with
  `SUPABASE_URL=http://127.0.0.1:54399`, a dummy anon key, `DATABASE_URL=` (empty).
- `e2e/auth-session.spec.ts` "(b) stays signed in across expiries": sign in, load `/app`,
  `/app/voortgang`, `/app/account`, `/en/app` for 15 s; never on `/inloggen`. **Run on the
  branch before the middleware change and record the result in `04-build.md`** (expected
  red: reuse detected), then after.
- In the auth spec: `authCookieOptions("https://vidalo.ai").secure === true` and
  `("http://localhost:3000")` false (the spec imports the module; `apps/web` has no unit runner).
- Header check (a): in the auth spec, every `set-cookie` starting `sb-` carries `HttpOnly`
  and `SameSite=Lax`; on a local production build in workerd (`pnpm --filter @vidalo/web
  cf:build` with `DATABASE_URL=` empty, then `wrangler dev`), the same, and the `/en/app`
  rewrite still delivers the refreshed `Set-Cookie` (OpenNext second pass). Secure is read
  back on staging/production over https by the delivery-lead.
