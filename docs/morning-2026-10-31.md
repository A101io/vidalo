Two API routes on vidalo.io never answer: `/api/scan/<token>/status` (the free check's waiting room) and `/api/support-autoreply`. Cause: on the Worker the database string is in the Hyperdrive binding, not in `DATABASE_URL`, and the web app reads that variable to tell mock from real. So production ran the web app's own code in mock mode: every route that awaits `ready()` first seeded eight demo scans into an in-memory database and hung. Same cause: the assistant answered from the FAQ with a key present, and domain verification accepted `simulate=1`. This predates tonight; no route that awaits `ready()` had been exercised on vidalo.io before, so the free check has never worked on the live site.

Fix: one line in `apps/web/worker.ts` (https://github.com/A101io/vidalo/pull/82). Verified in the local production build made the way CI makes it: without the line both routes time out at 40 s, with it 404 and 503 in under 0.25 s.
