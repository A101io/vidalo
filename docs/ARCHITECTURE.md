# Architecture (condensed)

Services: Web (landing, scan, result, checkout, dashboard) · Facts store (Supabase/Postgres) · Scanner · Fixer · Publisher · Reporter · job queue (Postgres table) + cron in worker.

Workflow A (acquisition): name+place → resolve business (Google Places + KvK; confirmation step prevents name collisions) → provisional facts scraped (site, GBP, KvK) → free scan: 6 prompts × 3 engines (chatgpt, google_ai, copilot) × 3 samples → extract/compare → provisional findings → result page (progress state shows prompts being asked) → email capture only to send report → Stripe Checkout (Instellen €149 one-off; Instellen+Bewaking €149 + €49/mo; iDEAL+card; btw-nummer) → webhook sets status trial, enqueues publish. No purchase: follow-ups day 7, day 21, then stop; result pages for non-customers deleted after 90 days.

Workflow B (setup, goal: live within 48h; owner does 4 things): confirm facts (facts v1, verified_at) → generate ~20 prompts → domain choice (A: CNAME feiten.{domain} → Vidalo, verified by polling DNS every 10 min; B: Vidalo registers {name}-{place}.nl; C later: WordPress plugin) → publish facts page (plain dated HTML, canonical, sitemap, JSON-LD LocalBusiness, llms.txt; IndexNow ping) → Google OAuth for GBP: read, diff, apply (hours, phone, website) → Bing Places + Apple Business Connect sync (approve diff) → directory sweep (~12 NL directories: API→sync, form→browser agent, email-only→templated request) → KvK mismatch → owner instructions → first full (baseline) scan → fix round 1.

Own-website check (`publisher/sitecheck.ts`, job `sitecheck`, at setup and every 30 days): reads `https://{domain}/robots.txt` (RFC 9309: most specific group, longest match) for the robots that answer questions, not training crawlers: OAI-SearchBot and ChatGPT-User (chatgpt), Googlebot (google_ai, gemini), Google-Extended (gemini), Bingbot (copilot), PerplexityBot (perplexity). Reads the homepage for "noindex" (meta or X-Robots-Tag), JSON-LD of a LocalBusiness (or an Organization with an address) and its telephone against the facts. Blocking issues (robot shut out, noindex, wrong phone) mail the owner the exact change once per new issue; missing business data is advice that rides along but never mails on its own. Events `sitecheck.done` / `sitecheck.notified`. Nothing on the site is changed by us.

Google index check (`publisher/google-index.ts`, job `index_check`, at setup when the host is verified, then daily until indexed and weekly after): with a service account (`GOOGLE_SERVICE_ACCOUNT_JSON`) Vidalo gets a Site Verification token, serves it as `<meta name="google-site-verification">` on the facts page (serve.ts), verifies the host, adds it to Search Console, submits `sitemap.xml`, then inspects `https://{host}/` with the URL Inspection API. State per business in table `google_index` (migration `0007_google_index.sql`); a new facts host starts over; each step resumes after a failure. Not indexed 14 days after the last sitemap submit → submit again (there is no API to request indexing of an ordinary page). Events `google_index.verified` / `.indexed` / `.checked` / `.failed`.

Workflow C (monthly scan): cron on anniversary day, runs spread 02:00–06:00 CET; 20 prompts × 5 engines × 10 samples (~€6–9). Engines: chatgpt (OpenAI Responses API + web_search, citations from annotations), gemini (grounding metadata), perplexity (sonar, citations), google_ai (SERP provider for AI Overviews / AI Mode, nl-NL), copilot (headless browser, lowest priority, skip on failure). Extract atomic claims keyed to fact fields (+ other_entity tag). Compare: wrong when ≥30% samples disagree; unstable 10–30%; phone wrong once is a finding. Attribute: fetch cited URLs, first one containing the wrong value = source_url; classify owned/directory/third_party/none. Persist findings with frequency ("7 van 10 keer") and diff vs last month (new/persisting/resolved). Drift alert if an engine's wrong-rate across customers jumps >20 points.

Niet gevonden: an answer in which the engine says it has no information ("geen informatie", "kan ik niet vinden", "I couldn't find", or an LLM extraction with zero claims and no business facts in the text) gets the sentinel claim `__not_found__` and the sample verdict `not_found`. It is never counted as wrong and never as correct. Per (fact, engine): ≥50% not-found samples → finding with `verdict: "not_found"`, `wrongValue: "niet gevonden"`, `sourceType: "none"`, no source URL; a wrong finding for the same key can exist next to it (upsert key includes the verdict). The report carries `notFoundAnswers` and `visibility`: `unknown` when ≥60% of all answers are not found, `partial` at ≥25%, else `found`. A business the AI has never heard of therefore reads as "niet gevonden", not as "nothing wrong".

Criteria and sector layer (docs/CRITERIA.md): every prompt and finding hangs on one of twelve criteria (`packages/core/src/criteria.ts`): 1 bestaan, 2 telefoonnummer, 3 openingstijden, 4 werkgebied, 5 spoed, 6 diensten wel, 7 diensten niet, 8 adres, 9 prijzen, 10 afspraken, 11 naamgenoot, 12 erkenningen. Each has a severity (1–5 afhaker, 6–10 misleider, 11–12 verwarring) and a threshold: criteria 1, 2, 8, 11 flag on one disagreeing sample ("any"), the rest at ≥ 30% of the samples ("ratio"); a wrong value below the threshold is "instabiel" (reported with `instable: true`, never persisted, never fixed). Not found is also judged per criterium and engine (≥ 50% of the samples → `criteriaNotFound`); not found on criterium 1 weighs as an afhaker. `FactKey` gained `area`, `urgency`, `credential`, `identity`; `Facts` gained `serviceArea {places, radiusKm}`, `urgency {available, hoursNl}`, `credentials[]` and `sector` (all optional, inside the facts JSONB), `Business` gained `sector` (migration `0003_sectors.sql`). Sector packs (`packages/core/src/prompts/sectors.ts`, 11 sectors) add, on top of the ~20 base prompts, up to 6 questions about the business and one recommendation question per intent (`RecommendationIntent`: quality "Wat is de beste loodgieter in Utrecht?", trust, now, specialty, price, place), pool "core"; plus a bank of 20–30 more recommendation questions (pool "bank": other phrasings, other places in the werkgebied, other services, seasonal ones with `season`). A full scan asks the core plus 6 bank questions that change every month, in-season ones first (`prompts/rotation.ts`); a bank question where the business is named in under half of ≥ 3 answers moves to the core (max 2 per monthly/baseline scan, event `prompts.promoted`). Stored prompts are topped up with newly generated ones before each scan (migration `0008_question_bank.sql`: `prompt.intent`, `pool`, `season`). The open intents probe `existence:beste|betrouwbaar|betaalbaar|dichtbij` (criterium 6, or 9 for price: misleider, so oranje, never rood) and only need the business to be open; the sector is inferred from the Google Places type or the KvK SBI code (`inferSector`, owner override wins). A recommendation prompt (`kind: "recommendation"`) is judged on one thing: is the business named (`mentionsBusiness`, fuzzy on normalised name + place). Absent → a finding on the linked criterium with `evidenceKind: "recommendation"`, `wrongValue: "niet genoemd"`, `correctValue` = the fact; present → correct. Position is never counted. Such a finding without a cited source takes the facts-page route (`RECOMMENDATION_PATH`, like not_found). The free scan stays at 6 prompts: existence, phone, Sunday hours + the recommendation questions for quality, trust and now (falling back to specialty, place, price). Every report carries `recommendations` (`scanner/recommendations.ts`): per recommendation question the answers that named the business, the other businesses named (read from list items and bold names, never a position) and the cited sites; shown as "Wie AI wel noemt" on the result page, in the baseline and monthly mails and in the CLI markdown.

Stipregel: colour per engine, then the worst colour among the engines with ≥ 10% NL use (`ENGINE_NL_USAGE`: chatgpt, google_ai, copilot, gemini count; perplexity does not). Per engine: grijs when ≥ 60% of its answers are not found (or no samples); rood on any afhaker finding, not found on criterium 1, or ≥ 30% wrong answers; oranje on a misleider/verwarring finding, fixes in progress, 25–60% not found, or > 10% instable answers; groen otherwise. `ScanReport` carries `stip`, `engineStips`, `findingsBySeverity`, `instable` and `criteriaNotFound`; emails, the CLI markdown and the dashboard show colour plus findings, never a score.

Workflow D (fix) — one path per source_type:
- owned_facts_page: republish + IndexNow; recheck 7d.
- owned_website: email owner exact page/text to change (WordPress plugin: patch); recheck 14d; reminders 14/28d.
- directory_api (GBP/Bing/Apple): resync; recheck 7d; operator if rejected.
- directory_form: browser agent submits; screenshot evidence; recheck 14d; operator queue on failure.
- third_party / email-only: templated correction email in owner's name (from vidalo.io, reply-to owner), follow-up 14d; recheck 30d; unfixable after 45d with note.
- other_entity: strengthen disambiguation on facts page ("niet te verwarren met"), sync place everywhere; recheck 30d.
- none (model memory): nothing; recheck after major model release; shown honestly.
- verdict not_found (any source type): there is no wrong source, so we make the business findable: publish facts page + sync all channels (GBP, Bing, Apple) + directory discovery; recheck after 21d; still not found → resync and follow-up recheck at 45d; never unfixable before 60d. Label: "Niet gevonden: we maken je vindbaar".
Sequence: finding → fix task → auto action within 1h, evidence stored → recheck = mini-scan of affected prompt/engine, 10 samples → resolved (proof card: before/after samples, dates, source) or next step/escalation. Owner notified only at resolution or unfixable.

Workflow E: monthly report email (status line, proof cards, open findings with source + next step), dashboard (facts edit → republish + resync + mini-scan after 7d; channels; findings timeline; proof cards; invoices; raw samples on request), Stripe billing €49/mo, dunning 14d → paused (scans stop, facts page stays 60d) → churned (facts page redirects to main site), cancel asks "Klopte alles al?" and offers quarterly check €29, re-engagement free re-scan after 90d, annual facts re-confirmation.

Cost per customer ≈ €11–14/month vs €49. Free scan ≈ €0.40.
